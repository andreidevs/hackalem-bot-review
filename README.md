# HackAlem Project Explorer

Локальный каталог публичных проектов **BAITC-Hacks**: поиск по README, 12 треков с исходными ТЗ, сравнение, предварительная оценка кода и чат с проверяемыми ссылками. Интерфейс и отчёты на русском.

## Запуск

Требуется Node.js **22.14+**. Для GitHub рекомендуется установленный `gh` с выполненным `gh auth login`. Для анализа — Codex CLI с `codex login` через ChatGPT либо Claude Code с `claude auth login` через подписку. API-ключи для моделей не нужны; приложения с авторизацией только по API-ключу не допускаются к анализу.

```sh
npm ci
npm run build
npm start
```

Открыть **http://127.0.0.1:4310**. `npm start` поднимает API и один worker. Терминал необходимо оставить работающим. Остановка: Ctrl+C. Повторный запуск восстанавливает незавершённые задания, а уже проверенные части кода берёт из кеша.

Для работы в фоне без открытого терминала: `npm run start:background`. Остановка фонового запуска: `npm run stop`. Лог находится в `data/runtime.log`. Эти две команды предназначены для macOS/Linux.

Для разработки: `npm run dev`, интерфейс **http://127.0.0.1:5173**. При обычном запуске серверы слушают только loopback. Приложение не предназначено для открытия в интернет.

## Запуск в Docker

Требуется Docker с Compose. API, интерфейс, worker, SQLite, Codex CLI и Claude Code работают внутри одного контейнера под непривилегированным пользователем. Порт опубликован только на `127.0.0.1:4310`. Внутри контейнера API слушает `0.0.0.0`, чтобы работало перенаправление Docker; проверки Host и Origin сохранены.

```sh
docker compose up -d --build
docker compose exec hackalem codex login --device-auth
docker compose exec hackalem gh auth login --hostname github.com --git-protocol https --web
docker compose exec hackalem npm run cli -- harnesses
```

Входить в Codex нужно через подписку ChatGPT. Если устройство не разрешает device auth, включите её в настройках безопасности ChatGPT либо перенесите существующий файловый вход:

```sh
docker compose exec -T hackalem sh -c 'umask 077; cat > /home/node/.codex/auth.json' < "$HOME/.codex/auth.json"
```

Секрет не попадает в образ или Git: копируется только в отдельный локальный volume `cli-home`. Системный Keychain macOS в Linux недоступен: если `auth.json` отсутствует, выполните вход внутри контейнера. Модель выбирается в «Обработка и настройки»; конфигурация хостового CLI автоматически не переносится. Для Claude Code выполните `docker compose exec hackalem claude auth login` и явно выберите его в настройках. GitHub CLI использует свой вход внутри контейнера; без него импорт ограничен анонимной квотой GitHub.

База, снимки и очередь хранятся в volume `catalog-data`, входы CLI — в `cli-home`. Обычные `down`, `up` и пересборка сохраняют их. **`docker compose down -v` удаляет базу и авторизацию.** В `.dockerignore` разрешены только файлы приложения; локальная база, отчёты и секреты не передаются в сборку.

```sh
docker compose logs -f --tail=100
docker compose stop                  # остановить API и worker
docker compose up -d                 # продолжить с сохранённой очередью
docker compose down                 # удалить контейнер, сохранить volumes
```

Для переноса существующей локальной базы в **пустой** Docker volume сначала остановите локальный процесс (`npm run stop` для фонового запуска, Ctrl+C для обычного), чтобы SQLite завершила работу с WAL. Не запускайте два worker на одной базе. После сборки импортируйте копию через stdin:

```sh
docker compose build
docker compose run --rm -T --no-deps hackalem sh -c 'test ! -e /app/data/catalog.sqlite && cat > /app/data/catalog.sqlite' < data/catalog.sqlite
docker compose up -d
```

Для резервной копии остановите контейнер и выполните `docker compose cp hackalem:/app/data ./docker-backup`, затем `docker compose up -d`. Копия включает SQLite и WAL; храните весь каталог вместе. Не публикуйте резервную копию в Git. После переноса локальная `data/` и Docker volume независимы.

## Работа

1. В «Обработка и настройки» проверить CLI. По умолчанию Codex использует модель из локального `config.toml`; поле модели позволяет выбрать другую доступную в вашей подписке. Запросы используют medium reasoning. Перехода на платный API нет.
2. Нажать «Обновить каталог»: загрузятся все страницы списка репозиториев, затем снимки исходников. Число проектов определяется GitHub, а не зашитым числом.
   Кнопка **«Оценить все проекты»** вверху запускает/продолжает очередь для всех проектов без актуальной оценки. Исходники загружаются при необходимости, анализ чередуется с загрузкой. Готовые оценки и пустые репозитории пропускаются; повторное нажатие не создаёт дубликаты активных заданий. После лимита подписки нажимайте её только при восстановленной квоте. Прогресс и ошибки доступны в «Обработка и настройки».
3. Поиск работает по названию команды, репозиторию, описанию, README, обзору и технологиям. Выбрать трек или технологию для фильтрации.
4. Открыть карточку: README, код, оценки, точные цитаты, версии анализа, заметки эксперта. Смена основного трека помечает прежние оценки устаревшими. Для пересчёта нажать «Анализировать».
5. Отметить 2–5 проектов и открыть «Сравнение». Выбор сохраняется при переходах внутри приложения, но сбрасывается при полной перезагрузке страницы.
6. «Рейтинги» показывает общий аналитический рейтинг либо оценку по конкретному ТЗ. CSV и Markdown доступны без вызовов AI. В настройках можно скачать отчёт о покрытии и кандидатах для экспертной проверки. Устаревшие и незавершённые оценки не ранжируются. В режиме «Топ-50 и топ-3 по трекам» кнопка **«AI-выбор топа по трекам»** передаёт модели до 10 лучших по баллам проектов каждого трека одновременно: модель сравнивает их между собой и выбирает топ-3 с обоснованием (один вызов на трек; треки с тем же составом финалистов пропускаются). Без этого выбора показывается порядок по баллам.
7. Чат использует выбранные проекты либо ограниченную поисковую выборку. Для вопроса о лидерах берёт до пяти текущих лидеров. Ответ содержит ссылки на сохранённые файлы; без источников выводы не создаются.

При лимите GitHub или подписки очередь становится на паузу. После восстановления квоты нажать **«Продолжить»**. Ошибочное задание можно повторить отдельно; есть отмена активного запроса. Пауза пользователя завершает текущий этап, отмена останавливает вызов модели.

## Хранение и воспроизводимость

- `data/catalog.sqlite`: проекты, снимки, файлы с исходными номерами строк, FTS5, оценки, промежуточные части, задания и заметки. WAL разрешает одновременную работу UI и worker.
- `sources/specifications.json`: все 12 предоставленных документов в исходном виде, URL и время изменения на момент чтения.
- `sources/policy.md`: явно обозначенная выжимка предоставленных пунктов положения, а не полный официальный текст.
- Google-документы зафиксированы в локальном пакете; кнопка обновления синхронизирует GitHub. Для новой редакции ТЗ нужно заменить пакет `sources/specifications.json` и перезапустить приложение. Версии ТЗ дополнительно сохраняются в `specification_snapshots`; старые оценки используют соответствующую версию. Кеш анализа зависит от SHA снимка, методики, ТЗ, выбранных CLI/модели и ручного трека.
- `HACKALEM_DATA_DIR` меняет каталог базы. Чтобы сделать резервную копию, остановить приложение и скопировать каталог `data` целиком. База и секреты не входят в Git.

Снимок относится к текущему коммиту default branch на момент импорта. Это не подтверждение, что такой код был сдан до дедлайна. Отсутствующие, архивные и пустые репозитории не удаляются из каталога.

## Методика

AI сначала определяет трек, затем читает исходники частями и формирует оценку. Для повторяющихся блоков передаются ссылки на точные копии; все исходные файлы сохраняются. Цитаты проверяются по пути, диапазону строк и точному тексту. Некорректные ответы не попадают в рейтинг.

В девяти ТЗ: соответствие задаче 25, реализация 25, README/воспроизводимость 25, ценность 15, потенциал/оригинальность 10. В AI Sana — отдельная шкала 20/15/25/15/10/10/5. Для двух кейсов «Электрокомплекта» общая шкала обозначена как аналитическая, потому что веса в предоставленных ТЗ отсутствуют. Общий рейтинг использует единую шкалу отдельно от трековой. При равенстве баллов места совпадают.

Оценка **предварительная и статическая**. Тесты чужих проектов, демо и программы не запускаются. README — заявление автора, наличие теста — не доказательство успешного запуска. Достоверность метрик, check-in, личный вклад и право на приз здесь не подтверждаются. Требования кейсов и баллы Demo Day не смешиваются. Сигналы нарушений передаются эксперту, а не превращаются в автоматическую дисквалификацию.

### Границы загрузки

Архив: до 30 МБ в сжатом виде, до 100 МБ распакованного содержимого, до 30000 записей. Снимок исходников: до 600 файлов и 12 МБ суммарно, до 300 КБ на файл. Зависимости, сборки, lock-файлы, двоичные данные и потенциальные файлы секретов исключаются. На вкладке «Исходники» видна причина каждого исключения. Если архив превышает лимит или недоступен, приложение запрашивает дерево GitHub и скачивает подходящие файлы отдельно по тому же SHA. Большие датасеты не скачиваются; усечённое дерево и ошибки отдельных файлов отмечаются в покрытии. Если источники получить не удалось, проект сохраняется с ошибкой загрузки.

Полный анализ тысяч репозиториев требует времени и расходует лимиты подписки. Каталог доступен в процессе; счётчики различают обнаруженные репозитории, скачанные исходники и завершённые оценки.

## Команды и проверки

```sh
npm run cli -- sync           # полный импорт через очередь
npm run cli -- sample         # два контрольных репозитория
npm run cli -- analyze 123    # анализ GitHub ID, снимок уже должен быть загружен
npm run cli -- status
npm run cli -- pause
npm run cli -- resume
npm run cli -- harnesses
npm test
npm run build
```

`npm run cli -- sync-now` выполняет только первоначальное перечисление репозиториев в текущем процессе и ставит скачивание в очередь; полезно при работающем длительном анализе. Не запускайте второй worker. `npm run cli -- smoke` делает короткий реальный запрос к Codex и расходует небольшую часть лимита.

Автотесты используют временную базу и подменённые ответы GitHub; реальные репозитории не запускаются. Браузерные сценарии находятся в `tests/e2e` (для самостоятельного запуска: установить браузер Playwright и выполнить `npm run test:e2e` при работающем сервере и загруженных контрольных проектах).
